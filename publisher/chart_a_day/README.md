# Chart Engine

`chart_a_day/` is the agent-driven chart-a-day pipeline for the Publisher product area. It bypasses the chatbot NL-to-SQL parser entirely: each backlog entry is a pre-defined question, the agent writes SQL directly against the Gold warehouse, renders a chart through `chart_engine_py`, and drafts social copy for human review before posting.

Use the queue CLI from `publisher/` with `PYTHONPATH=.`. `python chart_a_day/runner/run_next.py --status` shows backlog counts, `python chart_a_day/runner/run_next.py --next` shows the next ready question, and `python chart_a_day/runner/run_next.py --id q003 --note "..."` appends a review note to that question's output folder. The skill prompts live in `skills/sql_agent.md` (question to SQL and CSV), `skills/chart_request.md` (result CSV to `ChartRequest` and chart artifact), and `skills/social_copy.md` (finding plus chart to one canonical social draft, with platform-specific variants only when needed).

For manual Phase 5 parity runs, assume the validated Python environment is `.venv312`. It should carry both the editable `chart_engine_py` install and the `publisher/requirements.txt` Python dependencies so the same interpreter can handle DuckDB extraction and Python rendering. Use `chart_py.png` and `chart_r.png` as the parity artifacts, not `chart.png`. Geo renders may also need DuckDB `LOAD spatial`, `MPLBACKEND=Agg`, and a writable `MPLCONFIGDIR` to export reliably from the Python stack.
