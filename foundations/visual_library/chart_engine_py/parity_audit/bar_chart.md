## Verdict
- Overall parity status: `major`
- Primary missing layer: `render`
- Recommended fix order: spec contract first, variant/render parity second, export parity third

## Spec Parity
- Match: Python has a generated spec artifact and a working runtime contract for simple ranked bars.
- Gaps: the generated Python spec keeps only `entity`, `value`, and `subtitle`, while the R spec documents grouped, stacked, diverging, and highlighted peer variants plus richer required/optional fields.

## Prep Parity
- Match: Python prep keeps sorting, display order, labels, subtitle synthesis, and benchmark columns that already exist upstream.
- Gaps: the R prep layer carries more variant-aware shaping for shares and benchmark deltas; Python prep does not add that logic.

## Render Parity
- Match: ranked horizontal bars, direct labels, highlight color, and a benchmark line are present in Python.
- Gaps: the R bar contract includes grouped/stacked/diverging behaviors that the Python renderer does not expose.

## Theme / Defaults Parity
- Match: palette family and benchmark styling broadly follow the shared standards.
- Gaps: Python defaults to `Arial` via `pip_theme.yml`; R defaults to `Inter`.

## Export / Runtime Parity
- Match: Altair charts can export through `vl-convert`.
- Gaps: Python captions are stored in `usermeta`, not rendered into the visible export the way R captions are.

## Question Coverage Parity
- Supported: top/bottom ranking, within-scope ranking, highlighted peer comparison
- Partial: state benchmark-delta questions
- Missing: grouped/stacked composition and diverging-delta variants

## Gap Register
- [major] [spec] Generated bar spec collapses the R contract
  Evidence: `chart_specs/bar_chart.md` is a one-line artifact generated by `scripts/generate_chart_specs.py`, while `charts/bar/bar_spec.md` documents multiple variants, QA rules, and a larger field contract.
  Why it matters: CE/manual runs can validate only the thin Python contract, not the real R bar surface.
  Fix location: `chart_engine_py/scripts/generate_chart_specs.py`
- [major] [render] Python bar renderer only covers the ranked-horizontal path
  Evidence: `render/bar.py` implements one horizontal bar form with optional highlight and benchmark line; `charts/bar/bar_spec.md` explicitly lists grouped, stacked, 100% stacked, and diverging variants.
  Why it matters: question patterns documented for the R bar family are only partially portable to Python.
  Fix location: `chart_engine_py/chart_engine/render/bar.py`

## Recommended Follow-Up
- First: expand the generated spec so the Python runtime contract carries the full R variant surface.
- Second: port the missing grouped/stacked/diverging render semantics.
- Later: close the shared Altair caption/export gap.
