# Chart Engine — Build Plan

**Goal:** Ship two installable chart packages — a Python package (`chart-engine`) and an R package (`pip.charts`) — that share the same visual standards, the same 16 chart types, and the same data contracts. Both consumed internally by the chatbot, publisher, and Deep Dive; both publishable externally.

**Source of truth for design:** `visual_library/charts/<type>/` spec docs and `visual_library/docs/visual_style_guide_and_standards.md`  
**Source of truth for implementation:** this plan + `SPEC.md`

---

## Phase 1 — Theme and Standards

Everything else depends on this. Every render function calls the number formatters, palette helpers, and caption builder. Build this before any new chart types.

### Python

**`chart_engine/theme.py` — expand `Theme`**
- Full semantic palette: neutral (text, muted, axis, grid, border, background), highlight (selection, opportunity, strength, risk), diverging (better, midpoint, worse), quadrant (high_high, high_low, low_low, low_high), comparison (peers, neutral, benchmark), context/map (road, water, boundary, cluster)
- Output mode: `notebook` vs `presentation` — each with base_size, subtitle_size, caption_size, label_size, annotation_density, grid defaults, benchmark label defaults
- Per-chart-type config defaults — Python equivalent of `chart_default_config()` in `standards.R`. Each chart type (scatter, bar, line, boxplot, bump_chart, etc.) has sensible defaults that render functions read without needing hardcoded values
- Convenience accessors for all of the above (so render functions don't sprinkle `.get()` everywhere)

**`chart_engine/formatters.py` — number formatting**
- `format_percent(value, decimals=1)` 
- `format_dollar(value, compact=False)`
- `format_number(value, decimals=1, compact=False)`
- `format_integer(value)`
- `format_rank(value)`
- `format_year_range(start, end=None)`
- All driven by `NumberFormat` from `request.py` — render functions call `theme.format(value, request.number_format)` not their own logic

**`chart_engine/captions.py` — caption builder**
- `build_caption(source=None, vintage=None, side_note=None, footer_note=None, methodology_note=None)` → `str`
- `wrap_text(text, width)` utility used by render functions for subtitle and caption wrapping

**`chart_engine/pip_theme.yml` — canonical Patterns in Place theme**
- Ships inside the package as the default theme file
- Encodes every color, size, and mode default from `standards.R`
- External users copy this file and override for their own brand

**Update `__init__.py`** to export `formatters`, `build_caption`, and the expanded `Theme`.

### R

Wrap existing `shared/` code into a proper R package at `visual_library/r_package/`:

```
r_package/
  DESCRIPTION        ← name: pip.charts, version, dependencies
  NAMESPACE          ← generated by roxygen2
  R/
    standards.R      ← moved from shared/standards.R
    chart_utils.R    ← moved from shared/chart_utils.R
    data_contracts.R ← moved from shared/data_contracts.R
    formatters.R     ← number formatting helpers extracted from standards.R
    captions.R       ← build_chart_notes and related helpers
  man/               ← roxygen2-generated docs
  tests/
    testthat/        ← see Phase 4
```

Add roxygen2 doc comments to every exported function. Make it installable via `remotes::install_local()` or `remotes::install_github()`.

## Phase 2 — Chart Specs and Data Contracts

Fast phase. The design docs already exist in `charts/<type>/`. This is translation work, not design work.

For each of the 16 chart types, create `chart_engine/chart_specs/<type>.md` with YAML frontmatter derived from the corresponding `charts/<type>/<type>_spec.md`:

```yaml
---
chart_type: scatter
backend: altair
required_fields: [geo_name, x_value, y_value]
optional_fields: [size_value, label_flag, group, geo_id]
column_mapping: {}
default_benchmark: null
---
# one-paragraph implementation note (not a full redesign of the spec doc)
```

## Phase 3 — Prep + Render (per chart type)

One chart type at a time, following the 4-step pattern established by `bar_chart` and `line_chart`.

For each chart type:

1. `chart_engine/chart_specs/<type>.md` — YAML frontmatter (Phase 2 output)
2. `chart_engine/prep/<type>.py` — `prep_<type>(df, spec) -> df`
   - Uses `spec.column_mapping` and `spec.required_fields` — no hardcoded column names
   - Coerces types, drops/flags missing values per the spec doc's pre-processing section
3. `chart_engine/render/<type>.py` — `render_<type>(df, spec, request) -> chart_object`
   - Reads `request.theme` for all colors, sizes, mode defaults — no hardcoded values
   - Calls `formatters.py` for axis/label formatting
   - Calls `captions.py` for caption construction
   - Only implements the sub-configs (`benchmark`, `annotations`, `facet`) that are meaningful for this chart type
   - Altair types: return `alt.Chart`; matplotlib types: return `matplotlib.figure.Figure`
4. One line in `chart_engine/registry.py`

**R side:** each `shared/render/render_<type>.R` already exists. For each type:
- Move to `r_package/R/render_<type>.R`
- Add roxygen2 export comment
- Confirm it calls `resolve_chart_config()` and `visual_theme()` from the package rather than sourcing files directly

**Build order:** Altair types first (3–11), then matplotlib types (12–16). The matplotlib path introduces a new `_persist()` dispatch branch — validate that once on choropleth before doing the remaining 4 geo types.

## Phase 4 — Tests

Write tests in parallel with Phase 3, not after. Each chart type gets tests before the next one starts.

### Python (`chart_engine/tests/`)

**`test_contracts.py`**
- Missing required field → `ContractError` with correct message naming the field
- Empty dataframe after prep → `ContractError`
- All required fields present → passes silently

**`test_registry.py`**
- Every key in `CHART_REGISTRY` has a loadable spec file at the registered path
- Every `prep_fn` signature is `(df, spec) -> df`
- Every `render_fn` signature is `(df, spec, request) -> object`

**`test_orchestrator.py`**
- `validate_only=True` never calls any render function
- `output.save=True` calls `_persist()`
- Unknown `chart_type` raises `KeyError` with available types listed
- `return_prepped_data=True` attaches the df to `ChartResult`

**`test_skill.py`**
- Unmapped `question_type` + `inferred_shape` → raises `ChartMappingError`
- Ambiguous column inference (two equally-plausible dimension columns) → raises naming both
- Happy path → produces a `ChartRequest` that `render()` accepts without error

**Golden-file tests (one per chart type)**
- Fixed synthetic input df + `pip_theme.yml` → `chart.to_dict()` (Altair) or pixel hash (matplotlib)
- Saved to `tests/golden/<type>.json`
- Compared on every run — fails if the visual output changes unexpectedly
- Update golden files intentionally with `pytest --update-golden`

### R (`r_package/tests/testthat/`)

- `test_contracts.R` — `ensure_columns()` raises on missing fields; passes on valid input
- `test_prep.R` — each `prep_<type>()` returns a data frame with the expected columns
- `test_render.R` — each `render_<type>()` returns a ggplot object without error given valid input
- Golden PNG snapshots via `vdiffr` — one per chart type, compared on each run

## Phase 5 — Manual Integration: Deep Dive

Before wiring into the chatbot or publisher, manually run the package against a real Deep Dive section to validate that the charts actually look right, not just that they don't error.

**Target:** `metro-deep-dive/markets/jacksonville/act1_identity/s01_fingerprint.qmd`

**Steps:**
1. Install `chart-engine` locally into the Deep Dive environment (`pip install -e foundations/visual_library/chart_engine`)
2. Replace the `# TODO` Python block in `s01_fingerprint.qmd` with a real implementation: load KPI data, call `render()` with a `ChartRequest`, embed the Altair chart output
3. Render the full section with `quarto render s01_fingerprint.qmd`
4. Review the actual output: does it look right? Are the colors correct? Is the typography consistent? Are the benchmarks rendering?
5. Repeat for at least one other Deep Dive section that exercises a different chart type (e.g. a bar or line section)

This is the first real end-to-end test. If anything in the theme, formatters, or render logic is wrong, it will show up here before it's wired into automated pipelines.

**Success criteria:** A rendered Quarto HTML file with real data and charts that look like they belong to the same visual system — consistent palette, correct number formatting, proper captions.

## Phase 6 — Integration: Chatbot and Publisher

Once Phase 5 confirms the package works end-to-end with real data:

**Chatbot**
- Delete `publisher/chatbot/charts/renderer.py` (the R subprocess bridge — ~200 lines)
- Replace with calls to `render(ChartRequest(...))` from `chart_engine`
- The chatbot's `ResultProfiler` stays — it feeds into `question_to_chart_request()`
- The chatbot's `ChartSelector` is replaced by `question_to_chart_request()` from `chart_engine/skills/`
- Result: chatbot renders Altair HTML charts instead of R PNG files

**Publisher**
- `publisher/packager.py` calls `question_to_chart_request()` after `QueryExecutor`, before packaging
- Chart output paths flow through `OutputConfig` rather than temp directories
- Charts embed directly in the publisher output rather than as external PNG files
