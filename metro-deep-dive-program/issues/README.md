# Issues

`issues/` holds market-specific assembly and output planning.

This is where we keep:

- market-specific selections
- lock-once decisions
- notes on how routed analyses come together for one market
- shared issue-facing notebooks under `issues/_shared/` when they assemble
  reusable issue assets such as Act 1

Print visuals for an issue follow [VISUALS_BUILD_RULES.md](VISUALS_BUILD_RULES.md):
plan, then build one exhibit at a time, with review gates.

Reusable analytical logic should usually live in `analyses/`, but shared
issue-facing assembly notebooks can live here when they are composing issue
outputs rather than defining the analysis itself.
